# Quality for Lampac NextGen

Нативный модуль Lampac для Lampa: на постерах и полной карточке фильма/сериала показывает лучшую доступную метку `CAM / TS / TC / SD / HD / FHD / 4K`. **Тестовая версия:** пользователь подтвердил, что бейджи отображаются в каталоге и в полной карточке, а новое оформление выглядит хорошо. Пакетный кэш, фоновое обновление, улучшенный поиск сериалов и защита от рекламных раздач проверены CI; реальные результаты на отдельных фильмах ещё требуют проверки.

## Три независимые клиентские части

Исходники разделены без изменения адреса установки: `plugin.js` содержит определение и кэширование качества, `online-filter.js` — интеграцию «Источник в фильтре Онлайн», `buttons.js` — редактор кнопок полной карточки. Lampac объединяет их на сервере и по-прежнему выдаёт через **`/quality.js`**. При обновлении модуля необходимо заменить **всю папку**, иначе не будет дополнительных JS-файлов.

## Quality — кнопки

В настройках Lampa появился отдельный раздел **«Quality — кнопки»**:

- **Управлять кнопками** — включить/выключить собственную раскладку без удаления элементов других плагинов.
- **Показывать карандаш** — дополнительная кнопка на полной карточке, по умолчанию выключена. Её можно включить через настройки.
- **Настроить кнопки** — открывает редактор из настроек. Сначала нужно открыть хотя бы одну полную карточку, чтобы обнаружить доступные кнопки.
- **Сбросить настройки кнопок** — очистить собственный порядок, скрытие, режимы текста и папки.

Редактор позволяет менять порядок, скрывать/показывать кнопки, выбирать стандартное отображение / только иконку / всегда показывать текст, создавать папки и назначать им кнопки. При открытии полной карточки Quality также **сразу разворачивает штатную скрытую папку «Источник»**: «Онлайн», «Торренты», «Трейлеры» и другие реально доступные источники появляются отдельными кнопками, а исходная кнопка просмотра/выбора источника скрывается. Перемещается только родной контейнер `.buttons--container`, сами кнопки не клонируются, их обработчики сохраняются. При выключении управления кнопками контейнер возвращается на исходное место и штатный выбор источника снова работает. Состояние сохраняется в собственном ключе `quality_module_buttons_v1`, независимо от кэша качества и настроек сторонних плагинов. Раскладка не изменяет обработчики исходных кнопок и не клонирует сами кнопки: для разворачивания штатного меню переносится только их родной контейнер, сохраняя оригинальные DOM-узлы и события. Порядок задаётся через CSS `order`, видимость — собственными CSS-классами. Если браузер поддерживает `display: contents`, кнопки из штатной папки участвуют в общей перестановке с другими кнопками.

**Важно:** при тестировании нового редактора временно отключите исходный сторонний плагин расстановки кнопок: два независимых редактора одной панели могут конфликтовать. Штатная кнопка воспроизведения и управляющие элементы других редакторов не включаются в перестановку.

**Навигация с пульта:** редактор использует штатные `Lampa.Select` и `Lampa.Input`, не ставит глобальные обработчики клавиатуры, не вызывает `Controller.toggle` при отложенном обновлении, не забирает фокус у Онлайн, настроек или модальных окон. Карандаш добавляется до штатного включения контроллера полной карточки после события `full:complite`; после перехода на другой экран старые обновления не применяются. Поддержка всех нестандартных сторонних кнопок требует реальной проверки.

## Откуда берётся качество

Только из штатного `Lampa.Parser.get` с существующими настройками внешнего JacRed в `privateinit.js`. Quality не обращается к встроенному `Modules/JacRed`, не требует дополнительного URL или API-ключа и не передаёт их в Lampac.

## Установка/обновление

В установленном Lampac папка — `module/Quality/` (или `mods/Quality/`), а **не** исходная `Modules/Quality/`. При обновлении замените **всю папку**, включая `QualityCache.cs`, `QualityController.cs`, `ModInit.cs`, `ModuleConf.cs`, `manifest.json` и `plugin.js`; иначе серверная часть SQL не появится.

В тестовой ветке `manifest.json` содержит `"enable": true`. Если `BaseModule.LoadModules` содержит конкретный список, добавьте в него `Quality` (при `.*` не требуется). Перезапустите Lampac, затем перезагрузите Lampa (при необходимости очистите кэш `app.min.js`).

Для встроенной LampaWeb с `Quality.autoinject=true` модуль автоматически подключает `/quality.js` через `EventListener.AppReplace`. Если используете внешнюю Lampa, подключите URL `https://АДРЕС-ЛАМПАКА/quality.js` как JS-плагин. Если используете `LampaWeb.customPlugins`, **добавьте** Quality в существующий список, не заменяя другие записи.

Проверки: `GET /quality/status` должен вернуть `loaded:true`, `enabled:true` и `sqlcache:true`; `GET /quality.js` должен вернуть JavaScript. В консоли самой Lampa: `window.__qualityPluginLoaded` и `window.LampaQuality?.status()`. Диагностика не содержит ключей и адресов JacRed. `window.LampaQuality.status()` дополнительно показывает `sql_active_requests` (текущие запросы к SQL), `sql_retry_in_ms` (остаток паузы перед повторным использованием SQL) и `queued_requests`.

## Как устроен кэш

1. **Память Lampa:** быстрый ответ при повторном появлении карточки в текущей сессии.
2. **`Lampa.Storage`:** ключ `quality_module_cache_v6` сохраняет до 500 меток для повторного запуска; при смене JacRed источник перепроверяется.
3. **SQLite Lampac:** `database/quality-cache.db` с HTTP API `POST /quality/cache`. Здесь хранятся **только** случайный клиентский scope либо серверный хэш проверенной учётной записи, отпечатки источника/фильма, метка и TTL.
4. **Внешний JacRed через Lampa.Parser.get:** вызывается, только если действительного результата нет в предыдущих уровнях.

## Настройки Lampa — Quality

Плагин добавляет отдельный пункт **«Quality — качество»** в экран настроек Lampa (через штатный `Lampa.SettingsApi`). Параметры сохраняются на стороне Lampa, не в `privateinit.js`:

| Настройка | По умолчанию |
| --- | --- |
| Показывать бейджи | Да |
| Источник в фильтре Онлайн | Да (можно выключить) |
| Обновлять в фоне | Да |
| CAM / TS / TC: перепроверка | 1 день |
| SD / HD / FHD: перепроверка | 5 дней |
| 4K, последние 2 года | 10 дней |
| 4K, старше 2 лет | 30 дней |
| Ничего не найдено | 1 день |
| Размер пакета SQL | 30 |
| Фоновая проверка каталога | Каждые 15 минут |
| Обновить качество сейчас | Кнопка ручной перепроверки |

Периоды качества выбираются из 1, 2, 3, 5, 7, 10, 14, 21, 30, 45, 60 дней; размер SQL-пакета — 10/20/30; частота фоновой проверки — 5/15/30/60 минут. Ошибки JacRed не попадают в кэш.

**Stale-while-revalidate:** по истечении настраиваемого периода Quality продолжает показывать существующую метку (до 2 дополнительных дней), ставит её в низкоприоритетную очередь и обновляет по результату JacRed. Поэтому бейдж не должен исчезать между проверками. Фоновая перепроверка возможна **пока Lampa открыта**: сервер Lampac не имеет доступа к ключу внешнего JacRed и не может самостоятельно выполнять торрент-поиск на выключенных устройствах.

## Источник в фильтре Онлайн

Quality добавляет в **Онлайн → Фильтр** рядом с озвучкой и сезоном пункт **«Источник»**. Его основа — предоставленный пользователем **отдельный плагин** для Lampa: запись `{bal: true}` и открытие штатной кнопки `.filter--sort` через событие `hover:enter`. Под названием «Источник» показывается текущая подпись выбранного балансера из штатной кнопки — например, `Alloha - 2160p`, как в верхнем меню Онлайн. При следующем открытии фильтра подпись перечитывается, поэтому смена источника отражается автоматически. Если штатная подпись недоступна, остаётся «Выбрать балансер». При выборе пункта открывается **существующее** меню балансеров, а не копия списка источников в Quality. Выбор балансера, озвучки и сезона остаётся в штатном онлайн-плагине.

Quality учитывает, что стандартные Online / Online Prestige могут вызвать `filter.set('filter', ...)` **до** `filter.set('sort', ...)`: после получения сортировки пересоздаётся строка источника. При открытии меню также остаётся запасной обработчик `Lampa.Select.listener.preshow` для плагинов, которые создали фильтр до подключения Quality. Отдельный независимый плагин для встроенной функции **не нужен**.

Если экран Онлайн уже закрыт, настройку можно переключать из другого экрана: Quality больше не вызывает `Filter.set` у уничтоженного экземпляра, поскольку Lampa обнуляет его внутренние данные при `Filter.destroy()`. Новое открытие Онлайн создаст новый фильтр с актуальной настройкой.

**Настройки → Quality — качество → Источник в фильтре Онлайн** — отдельный переключатель, по умолчанию включён. Отключение убирает только пункт, добавляемый Quality; ни просмотр Онлайн, ни метки качества, ни торрент-раздел не выключаются. Существующий штатный пункт сортировки остаётся.

Если одновременно установлен **отдельный плагин балансеров**, который использует `__balancer_dual_patched` и `bal: true`, Quality старается не добавлять второй пункт. Однако переключатель Quality **не управляет самостоятельным плагином**: для проверки встроенной функции рекомендуется временно отключить отдельный скрипт и полностью перезагрузить Lampa.

Реальное отображение в браузере владельца ещё не подтверждено. [CI №75](https://github.com/ivzaislu/lampac-nextgen/actions/runs/41258470115) проверяет механизм `bal:true`, отсутствие дублирования строки, сохранение фильтров, отдельный переключатель и защиту от устаревших обработчиков в имитации Lampa.

**Подтверждённый случай Lampac Online.** Диагностика пользователя показала активность `lampac`, меню «Фильтр» с пунктами «Сбросить фильтр», «Перевод», «Сезон» и штатную кнопку с надписью `ИсточникPhantom ~ 2160p`. Прежний обработчик ожидал `online*` и подпись «Балансер», поэтому не находил нужное меню. Теперь поддерживается **точное** имя активности `lampac`, а «Источник» открывает уже существующую кнопку `.filter--sort`. Изменения ограничены этим онлайн-компонентом; функции Quality/JacRed и версия кэша `v6` не менялись.

### Если пункт «Источник» не появляется

При работе некоторых сборок Lampa `params.component` у `Lampa.Filter` отсутствует либо сам фильтр инициализируется позже. Интеграция распознаёт штатные поля `sort` с балансерами (`source`/`title`) и повторяет установку после `app/ready`. **Если компонент обошёл этот перехват**, Quality также может добавить пункт прямо при открытии меню через нативное событие `Lampa.Select.listener.preshow`. Выбор нового пункта открывает **существующий список балансеров** онлайн-плагина, без собственного списка или переписывания плеера. В диагностике после открытия страницы Онлайн выполните:

```javascript
window.LampaQuality?.status()
```

Обратите внимание на `online_filter_revision` (должно быть `6` после обновления `plugin.js`), `online_source_filter` (включена ли настройка), `online_filter_hook` (действительно ли перехвачен конструктор Lampa.Filter), `online_filters_detected` (число распознанных онлайн-фильтров) и `online_filter_sources` (число балансеров последнего распознанного фильтра). Если `online_filter_hook:true`, но `online_filters_detected:0`, это ещё не означает отсутствие нового пункта: для плагинов, создавших фильтр до Quality, добавлен отдельный перехват открытия меню. Проверьте также `online_select_hook` (подключение к нативному Lampa.Select), `online_select_menus` (число распознанных меню) и `online_select_inserted` (сколько раз пункт был добавлен). Откройте Онлайн → Фильтр **перед** вызовом `status()`. Если и новые счётчики нулевые, необходима диагностика фактического онлайн-компонента пользователя — CI не может установить её по одному имени плагина.

Исправление проверено на моделях штатного Online/Online Prestige, а также на вариантах без поля `component` и с поздней установкой Lampa.Filter — [CI №65](https://github.com/ivzaislu/lampac-nextgen/actions/runs/41255892679). Фактический интерфейс пользователя ещё требуется проверить.

## Пакетная обработка и ограничения

- Пакетное чтение `POST /quality/cache` с `op=get_batch` выполняет один SQL `SELECT` для группы из **до 30 фильмов**, а `op=put_batch` записывает группу одной SQLite-транзакцией. Клиент собирает пакеты с задержкой 150 мс, объединяет одинаковые фильмы, использует память/Storage до обращения к SQL.
- Штатный `Lampa.Parser.get` поддерживает **один фильм за запрос**, поэтому JacRed по-прежнему вызывается отдельно для каждого фильма, у которого нет свежего результата. Одновременно выполняются максимум **2** поиска; новые и видимые карточки имеют приоритет перед фоновыми, а общая очередь ожидания ограничена 300 задачами.
- Одновременно допускаются максимум **2 HTTP-пакета чтения** и **1 HTTP-пакет записи** в SQLite. При временной ошибке HTTP Quality пользуется `Lampa.Storage`/JacRed, а через **60 секунд** может снова обратиться к SQLite при следующем запросе. Если новых запросов нет, отдельное сетевое переподключение не запускается.
- База в `database/quality-cache.db` хранит записи до окончания настроенного срока + 2 дня. Массовое обновление из JacRed не запускается на сервере, чтобы не дублировать пользовательские секреты.

В SQLite одна таблица с периодическим удалением истёкших записей и ограничением порядка 25 000 результатов. База создаётся в рабочей директории Lampac; **сохраняйте папку `database` при обновлении**, если нужен старый кэш. По умолчанию параметр `Quality.sqlcache=true`; для отказа от серверного SQL установите `false` в конфигурации Quality — клиентский кэш останется.

SQLite используется, когда браузер поддерживает безопасный случайный идентификатор (`crypto.getRandomValues`), `fetch` и доступен URL Lampac. Внешняя Lampa может блокировать запросы к другому origin (CORS); в этом случае плагин автоматически использует локальные уровни и JacRed. **Не существует анонимного общего кэша для всех пользователей:** без авторизации записи разделены по браузерам; при проверенном аккаунте Lampac база может быть общей между устройствами этого аккаунта. Сервер не проверяет соответствие присланной клиентом метки реальному торренту.

## Проверки нагрузки и восстановления

[CI №57](https://github.com/ivzaislu/lampac-nextgen/actions/runs/41253738070) прошёл для двух сценариев в имитации Lampa: 150 карточек при тёплом SQL-кэше и 150 карточек при пустом кэше. Проверены пакетные чтения/записи по 30, лимит параллельных HTTP, сохранение 150 меток после повторной загрузки Lampa, переключение на JacRed при сбое SQLite и следующая попытка SQL через 60 секунд. Отдельно в запущенном опубликованном Lampac проверены **150 записей на запись и чтение** через пакетный HTTP API.

Это воспроизводимые тесты Node.js и GitHub Actions, **не реальные замеры скорости на телевизоре**. В реальной Lampa ещё нужно проверить долгий сеанс с фоном, 100+ видимых карточек и доступность SQL за пользовательским прокси.

## Включение и отключение без потери кэша

В настройках Lampa переключатель **«Показывать бейджи»** убирает метки с постеров и открытой полной карточки. После включения возвращаются действительные результаты из кэша или запускается новый поиск. При смене JacRed предыдущие метки скрываются, а ответы старого источника не должны вернуться в интерфейс.

Эти сценарии проверены в [CI №60](https://github.com/ivzaislu/lampac-nextgen/actions/runs/41254363467) на имитации Lampa. Реальные длительные тесты на телевизоре и за пользовательским прокси **отложены**. Версия кэша остаётся v6; очищать SQLite или Lampa.Storage не нужно.

## Оформление

- Постер — снизу слева на штатном месте `.card__quality`. Если CUB/Lampa уже добавила свою плашку `.card__quality`, Quality **временно скрывает её**, пока показана наша подтверждённая метка. Оригинальный DOM-элемент не удаляется и снова виден после выключения Quality, смены JacRed или отсутствия результата. Позднее добавленные CUB-плашки скрываются тем же CSS-правилом; на реальной Lampa это ещё требуется проверить.
- Полная карточка — в строке рейтингов, класс `.full-start__status`.
- `CAM/TS/TC` — красный, `SD` — оранжевый, `HD` — синий, `FHD` — фиолетовый, `4K` — зелёный.



### Если фильм или сериал остаётся без бейджа

Quality ищет по оригинальному и локализованному названию, выбирая лучшее качество среди найденных релизов, а не останавливаясь на первом HD/FHD. Для старых фильмов, пока нет 4K, возможен один дополнительный поиск без фильтра по году. Например, `WALL·E`, `WALL-E` и `WALLE` учитываются как близкие варианты названия при проверке раздач. Для сериалов, выпущенных много лет назад, если поиск с годом премьеры ничего подходящего не нашёл, он повторяет поиск без ограничения по году через штатный `Lampa.Parser.get({from_search:true})`. Результаты без явного указания сериала, сезона или эпизода, а также трейлеры, тизеры, реклама, проморолики, видеонарезки и полнометражные фильмы с похожим названием отбрасываются. Например, полнометражный фильм `South Park: Bigger, Longer & Uncut` не должен задавать качество сериалу `South Park`.

**Важно при обновлении до версии v6:** накопленные ранее метки (даже положительные) перепроверяются, поскольку среди них могли быть рекламные ролики или другой фильм. Данные прежних ключей `quality_module_cache_v2/v3/v4/v5` не удаляются, но новый код их не использует. Отпечаток SQLite-источника тоже меняется, поэтому возможен единовременный повторный поиск; действуют прежние ограничения очереди и пакетного кэша. После установки полностью перезагрузите Lampa. Кнопка `Quality — качество → Обновить качество сейчас` предназначена для повторной проверки уже известных карточек.

Если после обновления какой-то фильм всё ещё не получает качество, нужны **название, год и тип (фильм/сериал)**, а также пример названия релиза из обычного поиска торрентов Lampa, без адресов/API-ключей JacRed. Без конкретного примера нельзя достоверно определить, не нашёл ли JacRed релиз вообще или Quality его отфильтровал.

### Ограничения фильтра

Даже строгая проверка заголовка не гарантирует, что торрент содержит полный фильм или серию: некоторые рекламные раздачи не отмечены как реклама и могут иметь ложные метаданные. Для точной диагностики оставшихся ошибок нужны **название релиза из обычного поиска Lampa** и название/год фильма или сериала. Адреса и ключи JacRed не присылайте.


### Почему мультфильм может ошибочно получать HD

В реальной выдаче JacRed для «ВАЛЛ·И» (2008) находились 108 раздач, 20 из них с числовым качеством 2160 (4K). Их поле \`types\` содержит \`multfilm\`, иногда одновременно \`multserial\`. До исправления Quality отвергал такие результаты для фильмов, поскольку ожидал только \`movie\`/\`film\`. Теперь \`multfilm\` допустим для фильма; для TV неоднозначная пара \`multfilm\`+\`multserial\` требует дополнительных признаков сезона/серии. Поддерживаются также названия \`name\`/\`originalname\` из ответов JacRed.

Результаты взяты из предоставленного пользователем снимка открытого JacRed v1, а не из живой проверки \`Lampa.Parser.get\` на его устройстве: Lampa использует другой endpoint. Тесты хранят только заголовки, годы, качество и типы; адреса трекеров, magnet и IP в репозиторий не добавляются. Версия кэша \`v6\` повторно проверит прежние HD и FHD.

## Ограничения и проверки

[CI GitHub Actions](https://github.com/ivzaislu/lampac-nextgen/actions/workflows/quality.yml) проверяет .NET 10, Node.js, HTTP API, SQL и динамический запуск. [PLAN.md](PLAN.md) содержит журнал с успешными и неуспешными прогонами.

Команды: `dotnet build Modules/Quality/Quality.csproj`, `node tests/quality-client.test.js`, `node tests/quality-cache-client.test.js`, `node tests/quality-batch-client.test.js`. Проверка Node — имитация Lampa, не тест физического телевизора. Серверное SQL API принимает результаты клиента, поэтому глобальный публичный кэш не включён; rate-limit, CORS и поведение за пользовательским прокси предстоит проверить в реальной установке.
