## Зафиксированная архитектура

**Решение владельца от 2026-10-31: НЕ использовать встроенный Modules/JacRed Lampac.** В личном privateinit.js уже настроено подключение к внешнему JacRed, с которым работает сама Lampa.

В [Lampa Parser](https://github.com/ivzaislu/lampa-source/blob/main/src/core/api/sources/parser.js) проверены переменные Lampa.Storage: jackett_url, jackett_key, jackett_url_two, jackett_key_two, parser_use_link, parser_torrent_type. Публичный Lampa.Parser.get использует эти настройки, выбирает источник и возвращает Results. Поэтому Quality должен обращаться к **Lampa.Parser.get**, а не делать отдельный запрос к JacRed.

**Схема v2 (тестовая ветка):** Lampac Quality раздаёт `/quality.js` и клиентский JSON API `/quality/cache`. Клиент вызывает существующий `Lampa.Parser.get`, определяет лучший бейдж и последовательно использует память Lampa, `Lampa.Storage`, опциональный серверный SQLite. Сервер получает только `scope`, 16-символьные отпечатки источника/фильма и метку качества; **не получает URL, ключи и сырые результаты JacRed**. Нет второго JacRed, Node.js и собственного WS. В репозитории `privateinit.js` только шаблон; рабочий личный файл пользователя недоступен.

**Ограничение доверия:** клиентские метки не являются криптографически подтверждёнными сервером. SQLite строго разделяет данные по случайному 128-битному идентификатору браузера, а при проверенной учётной записи Lampac — по серверному хэшу аккаунта. Это предотвращает случайное смешение кэшей пользователей, но не делает присланные тем же клиентом метки доверенным источником. Поэтому не включён анонимный глобальный кэш для всех клиентов. API не принимает URL, не выполняет серверных обращений к JacRed (нет SSRF) и не изменяет `Shared` или `Modules/JacRed`.

### 2026-10-31 — защита от рекламных роликов и качества чужого фильма

- Пользователь сообщил о ложном HD у «Южного парка» и отсутствии меток у «Симпсонов»/«Гриффинов». **Конкретные названия торрентов и реальные ответы JacRed не предоставлены**, поэтому причина каждой метки остаётся гипотезой.
- По [lampa-source Parser](https://github.com/ivzaislu/lampa-source/blob/main/src/core/api/sources/parser.js) подтверждено: обычный `Lampa.Parser.get` передаёт год премьеры и категорию 5000, а `from_search:true` отправляет поисковую фразу без этих фильтров. Это может помогать многосезонным сериалам, начавшимся десятилетия назад.
- В `plugin.js` добавлен отбор рекламных раздач (trailer, teaser, promo, commercial, TV spot, sample, clip, реклама, анонс, проморолик и т. п.). Маркер ищется вне совпавшего оригинального или локализованного названия — сериал `The Trailer Park Boys` не считается рекламой из-за слова Trailer в своём имени.
- Для `item.type=tv` при отсутствии `Info.types` требуется обозначение сезона, эпизода, интервала лет или сериала. Результаты с типом `movie` не подходят к сериалу даже при совпадении названия. Сильно отличающийся год релиза принимается лишь с признаками нового сезона. Тем самым полнометражный `South Park: Bigger, Longer & Uncut` не должен дать сериалу случайный HD.
- После безрезультатных оригинального и локализованного запросов сериал получает резервные поиски по названиям без параметра года через штатный `Lampa.Parser.get({from_search:true})`; сохраняется максимум два одновременно активных задания и SQL-batch. Возможны дополнительные запросы для сериалов без найденного качества; серверный JacRed не используется.
- Чтобы удалить старые возможные ложноположительные данные, локальная версия повышена с `quality_module_cache_v3` до `v4`, изменён отпечаток источника для SQL. **Положительные и отрицательные v2/v3 не мигрируют**, поскольку могут быть неправильными; все метки постепенно определяются заново.
- Дополнены Node-тесты на три названных сериала, типичные рекламные заголовки, чужие полнометражные фильмы, отбрасывание неопределённых раздач, yearless fallback с `Lampa.Parser.get`, SQL-кэш и защиту от поздних ответов.
