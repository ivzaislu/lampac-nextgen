# Quality — план разработки и учёт прогресса

> **Цель:** новый нативный модуль для Lampac NextGen, который показывает лучшее доступное качество фильмов и сериалов в Lampa. Мы переносим **функциональность**, не копируем архитектуру старого Node.js-сервера.
>
> **Рабочий репозиторий:** https://github.com/ivzaislu/lampac-nextgen  
> **Рабочая ветка:** `feature/qulity-lampa-module` (ответвление от `main`)  
> **Каталог:** `Modules/Quality/`  
> **Правило:** `main` и исходные репозитории не редактировать; выполненное отмечать только после проверки.

## Правила отметок и готовности

- `[x]` — работа **выполнена** (при наличии проверки описать её в журнале).
- `[ ]` — работа **не выполнена** либо ещё **не проверена**. Исследование исходников не равно успешной интеграции.
- После каждого изменения обновлять соответствующие чекбоксы и запись **«Журнал»**: факт, проверка, ограничения, следующий шаг.
- Исходный режим `manifest.enable=false`: модуль не должен включаться в рабочем Lampac до проверки.
- Повторно используем JacRed, `TorrentDetails`, `HybridCache`, `ModuleInvoke`, события Lampac и NWS.
- **Не добавляем:** второй Node.js-сервер, копию JacRed, отдельный WebSocket-сервер, SQLite только ради временного кэша.
- Предпочитаем проверяемое минимальное решение; не добавляем резервные абстракции «на будущее».

## Этап 3. Кэширование

- [ ] Использовать `Shared.Services.Hybrid.HybridCache`; по возможности асинхронный путь чтения.
- [ ] Разделить «пора проверить» и «удерживать предыдущее качество» (stale-while-revalidate).
- [ ] Различать достоверное «не найдено» и временные ошибки источника.
- [ ] Начальные сроки из оригинала: CAM/TS/TC — 1 день; SD/HD/FHD — 5 дней; 4K нового контента — 10 дней; 4K старого — 180 дней; отсутствие результата — 1 день.
- [ ] Возвращать сохранённую метку во время обновления/сбоя.

**Готовность:** повторная загрузка карточки не запускает ненужный поиск; ошибки JacRed не стирают кэш.

## Этап 4. Очередь и ограничения

- [ ] Одна задача на ключ контента (`single-flight`).
- [ ] Ограничить параллелизм, глубину очереди и длительность операций.
- [ ] Retry/backoff только для временных ошибок и rate limit.
- [ ] Освобождать фоновые задачи через `CancellationToken` при выгрузке.
- [ ] Не сканировать без необходимости все ранее запрошенные карточки; использовать `Channel<T>`/`SemaphoreSlim` только если нужны.

**Готовность:** 100 одинаковых запросов не дают 100 независимых поисков; очередь ограничена.
